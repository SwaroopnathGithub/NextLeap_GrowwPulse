How the n8n Workflow Works

The automation that turns the review analysis into a drafted pulse, a human approval step, and queued deliverables — nothing goes out automatically.

Runs locally via Docker LLM: Groq Human approval gate Gmail draft only — never sent

What we've done so far

  1. Scraped 12,637 Groww Play Store reviews (last 12 weeks, com.nextbillion.groww, India) with scripts/scrape_reviews.py.
  2. Analyzed them for rating trends and 9 recurring themes, and confirmed a clear, recurring fee/charge confusion signal (brokerage charges perceived as unexpectedly high) with scripts/analyze_reviews.py and scripts/weekly_pulse_data.py.
  3. Drafted the two deliverables by hand first — the Weekly Product Pulse and the Fee Explainer — as the reference version of what the workflow should produce.
  4. Built the n8n workflow (n8n/groww-pulse-workflow.json) that reproduces that same drafting step with an LLM, gated behind a human approval, so this can run on a recurring cadence (e.g. weekly) without manual re-analysis each time.
  5. Published this static site as the always-visible version of the deliverables, independent of whether the workflow has run recently.

The workflow, step by step

1. Manual Trigger

Starts the workflow run. (Can be swapped for a Schedule Trigger later to run weekly automatically — kept manual for now so each run is a deliberate, reviewable action.)

2. Review Analysis Data Set node

Carries the condensed output of the analysis scripts into the workflow: the rating distribution, the 9 theme frequencies, the week-over-week trend, and the representative fee-complaint quotes — the same numbers behind the Product Pulse and Fee Explainer pages on this site.

3. Groq Chat Model + Basic LLM Chain Draft Pulse & Fee Explainer

Feeds that analysis data to an LLM (via Groq) with a prompt asking for two short sections in markdown: a condensed Weekly Product Pulse and a Fee Explainer — mirroring the structure of the two reference docs on this site, but generated fresh from the current data each run.

4. Approval Gate Wait node — the key control

The workflow pauses here. Nothing is written to the Doc or drafted in Gmail until a person explicitly resumes it. Resuming means opening the Resume URL that n8n shows for the paused execution. If nobody opens it, the run simply stops here — reject-by-default, not send-by-default.

5a. Append to Pulse Doc Google Docs node

Only runs after approval. Appends the approved pulse + fee-explainer text, dated, to a running Google Doc — so there's a running history of every approved weekly pulse, not just the latest one.

5b. Create Gmail Draft Gmail node — draft only

Also only runs after approval. Creates a Gmail draft with the same content — it is never sent automatically. A person still has to open it in Gmail and hit send themselves if they want it to go out.

Why it's built this way

  • Approval before any write — an LLM draft is a starting point, not a finished communication. The Wait node makes sure a person reads it before it touches a shared doc or an inbox.
  • Draft, not send — even after approval, the email step stops at "draft." Sending is a separate, deliberate human action.
  • Separation of credentials — the workflow references Groq/Google Docs/Gmail credentials by name but doesn't create or store them; those are configured directly in n8n by whoever owns the account.

Full import instructions and node-by-node configuration notes are in n8n/README.md in the repo. The workflow JSON itself is n8n/groww-pulse-workflow.json.

What's next (not yet done)

  • Point the Set node at a live data source (e.g. a re-run of the scrape + analysis scripts) instead of a fixed snapshot, so each run reflects the latest reviews.
